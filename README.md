Що було зроблено у 2-й лабораторній:
Згідно з вимогами, до існуючої ієрархії (в якій вже використовується **Наслідування** з глибиною 4 рівні) було додано два нових типи зв'язків між об'єктами: **Композицію** та **Агрегацію**.

1. Додано зв'язок "Композиція" (Composition)
Композиція — це жорсткий зв'язок, коли один об'єкт повністю керує життєвим циклом іншого. 
Як реалізовано:** Створено новий клас `MessageContent` (для зберігання заголовка і тіла повідомлення). Цей об'єкт створюється безпосередньо всередині конструктора класу `PushNotification`. Якщо видалити об'єкт `PushNotification`, його `MessageContent` також буде знищено.

2. Додано зв'язок "Агрегація" (Aggregation)
Агрегація — це м'який зв'язок, коли один об'єкт містить інші об'єкти, але вони можуть існувати незалежно від нього.
Як реалізовано:Створено новий клас `NotificationCenter`, який приймає готові об'єкти типу `Notification` у вигляді списку. Об'єкти повідомлень створюються окремо (в `Main.java`) і передаються в центр оповіщень. Якщо видалити `NotificationCenter`, самі об'єкти повідомлень продовжать існувати.


Зміни у файлах проєкту:

Створені НОВІ файли:
1. `MessageContent.java` — новий клас для демонстрації **Композиції**.
2. `NotificationCenter.java` — новий клас для демонстрації **Агрегації** (керує чергою повідомлень).

Змінені ІСНУЮЧІ файли (з 1-ї лаби):
1. `PushNotification.java` — оновлено конструктор та методи для використання композиції (додано об'єкт `MessageContent` всередину).
2. `Main.java` — повністю оновлено логіку тестування. Тепер об'єкти створюються і передаються у `NotificationCenter` для демонстрації агрегації.

Загальна кількість класів та інтерфейсів у проєкті: **10** (вимога: мінімум 6).
Глибина ієрархії: **4** (вимога: мінімум 3).
Кожен клас знаходиться у своєму окремому файлі.
